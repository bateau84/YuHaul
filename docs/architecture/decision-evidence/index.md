# Decision evidence and metadata lifecycles

The user should recognize a Backtest video and see the cause actually recorded for that run. Local display metadata and historical evaluated input are different facts. New evidence must identify the causal exclusion, not infer it from today's rules.

The overall design is **provisional**, while the implemented current/local read slice has an **accepted bounded wire contract**. An accepted decision and exact specification select **future config-only causal exclusion identity** without storing compared provider input; implementation/composed proof remain outstanding. BR-015 AC10–13 require the actual first cause in production and every simulation mode, visible in list and detail. Generic-only new skips fail, including a new evaluation of a video with old history. **Legacy scope is resolved:** the user accepts old generic-only rows displaying “rule unavailable” in list/detail, preserving supported skip/overall outcome and remaining explicitly incomplete and unchanged on reuse. Never infer or backfill their cause. Full historical reproduction outside that boundary and durable-title preservation remain blocked by provider retention; neither legacy acceptance nor a pointer recovers input or grants retention permission. Configured values still require positive release eligibility; snapshot type/value alone proves no origin. No retention extension or backfill is authorized.
