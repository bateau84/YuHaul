**Status:** provisional for complete historical evidence — the independent current/local reader is implemented and its bounded wire contract is accepted in [ARS-001 — Current-Local Run-Video Metadata](../specifications/ars-001-current-local-run-video-metadata.md). Complete historical-evidence realization remains blocked by unresolved retention authority. No new storage permission, requirement amendment, full implementation acceptance or live Run15 diagnosis.

[ADR-001 — Capture the Causal Exclusion as an Immutable Snapshot Reference](../decisions/adr-001-capture-causal-exclusion-snapshot-reference.md) selects a second independent slice for **future** decisions: capture which configured rule caused the skip, with no new provider-input storage. [ARS-002 — Causal Exclusion Capture and Inspection](../specifications/ars-002-causal-exclusion-capture-and-inspection.md) now fixes its persistence, producer/recovery and list/detail contracts. Implementation and composed proof remain outstanding. This answers rule identity without fulfilling the blocked independent reproduction promise. BR-015 AC10–13 make this mandatory in every supported production/simulation mode and both inspection surfaces; generic-only new skips are not conformant. Under the user-approved AC13 boundary, old generic-only rows may display “rule unavailable” and remain explicitly incomplete, never inferred or backfilled. A new evaluation of the same video still requires its actual causal rule.

The system will show locally available title, source-channel name and duration beside the selected run's recorded decisions. It will label that information as current/local context, not the input used by the historical run. A new exclusion record must identify the particular predicate that actually caused the skip. Old generic records remain inspectable, explicitly incomplete and unchanged.

For example, a new Backtest can record that one route excluded a video because its title contained a configured phrase. Inspection can explain that route's comparison, while another route's simulated match remains a separate hypothetical result. A later title refresh must not rewrite the recorded comparison. If the old compared title is no longer permitted to be retained, it cannot be presented as available or reconstructed from the refreshed title.

There is no established complete realization of the accepted long-term promise today. Ordinary provider policy does not establish permission for indefinite historical API-title/description snapshots. A stored Boolean, lossy fingerprint or current title cannot independently reproduce an arbitrary historical text comparison. Only a permitted retention basis, or an explicit user-owned amendment of the affected promises, can close this gap. **Do not begin dependent full evidence-storage implementation or mark BR-015 AC7/BR-009 fulfilled from this proposal.** Independent local-read and unavailable-state improvements do not depend on that decision.

## Constraints and forces

- Keep the existing single-process application, SQLite database, run snapshots, route identities, endpoint membership and outcomes. No new service, event store, full-metadata archive or distributed coordination is justified.
- Preserve exclusion order, normalization, route order, final/disabled skips, conditions, duplicate behavior and action semantics. Evidence records what happened; it must not change which predicate wins.
- Separate three concerns: recording the cause, retaining the actual compared input, and releasing safe information to inspection. Storing a copy in an audit does not change its origin or retention obligations.
- Preserve accepted historical guarantees until their owner changes them. Lack of permission is a blocker, not authority to silently cap history or remove title persistence.
- Do not alter date meaning, Run15 state, live runs, credentials, queue policy or deployment. Those have separate owners.

## Decision and conceptual interface contracts

### Independent safe read boundary

Keep `GET /api/runs/{id}/videos` and `GET /api/runs/{id}/videos/{videoId}`. Resolve run membership before local enrichment. Use one shared projection policy for list and detail; enrich only the requested page, preferably with a bounded batch lookup. There is no need for a new public metadata endpoint or a browser request per row.

Add a distinct display-context object conceptually containing title, source-channel display name and duration in seconds, plus each field's availability and known observation/fetch time. Present fields independently: one missing title must not hide a known duration. Zero seconds is a value, not absence. Returned names are current/local unless captured historical provenance establishes otherwise. A field without a trustworthy observation time must not acquire one from run start or discovery time.

Use only a local reader with no refresh capability. Reuse `GetDisplayMetadata`'s lifecycle checks, or a batched equivalent with the same or stricter release boundary; do not call `GetDisplayTitle`, `RefreshOnDemand` or `RunLifecycle`. The existing method uses a strict-before expiry check; the new release boundary must withhold at the expiry deadline as well, rather than rely on a cleanup job having run. Do not resurrect retained duration/publication values from an inactive/expired row. Do not fall back to `channel.name` until that field's own provenance and freshness are established.

Availability is field-specific and separate from routing outcome: available value; unavailable with unknown cause; known expired; known not captured; withheld; or read failure. These are evidence states, not new run/video outcome categories. An absent database row after cleanup usually proves only unavailable, not expired or never recorded. A legacy record known to predate causal capture can truthfully say its specific exclusion was not captured. A metadata query error must leave successfully read decisions usable and supply a safe context-read failure; retry remains local.

Preserve the existing category in both list/detail. A summary may say “route exclusion recorded; specific rule unavailable.” It cannot choose an arbitrary excluded route as the cause of the whole video's outcome. Route labels need provenance: snapshot label, current/local fallback, or unavailable. Current fallback remains useful only when not represented as a run-time label. Missing run mode must not default to production language.

This read slice requires no evidence-storage migration. [ARS-001 — Current-Local Run-Video Metadata](../specifications/ars-001-current-local-run-video-metadata.md) now supplies the authoritative exact fields, nullability, producer/reader rules and bounded verification record. The conceptual descriptions here are not alternate wire names or a historical-input schema.

#### Focused local-reader realization (selected 2026-11-06)

This selects the dependency/lookup structure for the independent read slice only. Production now injects the existing `metadata.Manager` through `server.WithMetadataReader`; its narrow server field exposes only `ReadLocalDisplay`. The manager uses `Store.readLocalDisplayRows`, returns keyed `LocalDisplay` results, and samples the cutoff after the query is consumed. This implements the selected **server-owned, single-method batch display-reader interface**, without giving the server refresh/fetch methods. Before this repair the manager was supplied only to the pipeline. Exact emitted fields and eligibility are in the linked ARS, not inferred from these internal names.

The manager implements this local-only batch method using one new bounded, parameterized Store query, not a loop over `GetDisplayMetadata`. Store selects only IDs, title, channel name, duration and the lifecycle timestamps/flags needed for eligibility. Manager owns eligibility and converts rows to minimal display results; Server owns HTTP projection. Return neither `TransientMetadata` wholesale nor descriptions, thumbnails, fingerprints or provider bodies. This keeps lifecycle policy in its existing package without a new service or an adapter that imports Server from metadata.

Why this choice: injecting raw Store into Server would duplicate lifecycle checks in handlers; injecting the existing single-ID manager method would add one metadata query per list row. A SQL join inside run-state queries would entangle run membership with Store A lifecycle. The batch reader adds one small seam and reuses existing ownership. It does not fix the existing per-video route-decision queries, which are outside this bounded metadata change.

**Batch and release contract:**

- List enriches only external IDs from the successfully read current page (maximum currently 100). Detail enriches only its one successfully resolved requested-run member. No lookup for an invalid/not-found run or unrelated video; an empty page performs no metadata query. Deduplicate IDs and use placeholders, not interpolated ID text. An internal caller exceeding the bounded batch contract must not trigger an unbounded lookup or silent truncation.
- Complete mandatory run/video/route/action reads first. Perform the local context lookup near response projection, with the manager's injected clock read after the Store result has been consumed. Use one projection-time cutoff across the batch, not request-start time. This gives one metadata SELECT per nonempty page and one for detail, independent of page length; no per-item fetch, retry, cache warming or lifecycle write.
- Release a value only from an active row with no expired marker, usable lifecycle timestamps and an expiry strictly after the projection cutoff. Withhold all values at the exact deadline or after it, regardless of whether cleanup has run. A known past deadline/expired marker supports expired status; inactive alone does not establish historical expiry or capture absence. An actually present value deliberately suppressed by the current release check may instead be marked withheld, as qualified below. Missing/unusable timing does not prove fresh data or a known expiry cause. No new TTL or retention extension is introduced.
- Successful lookup with no row yields unavailable with unknown cause, not not-found decision, never-recorded or expired. On an eligible row, each null/empty title or channel name remains unavailable; a known zero duration remains available. Return only original permitted strings, not IDs/hashes as substituted names. Observation/fetch time, when supported, is from that row, never the historical run timestamp. All released context is explicitly current/local cached information, not run input.
- A query, row scan or iteration error fails the optional batch as a read. Discard partial lookup results rather than interpreting unvisited rows as absent. Do not return partial raw values alongside an error. Do not expose the database error text. Successful mandatory evidence still returns normally (HTTP 200) with context marked read-failed and values withheld; a context retry rereads the same local run/video endpoints. Mandatory evidence errors retain their existing HTTP behavior. An unconfigured reader is an explicit context-read failure, not a fabricated successful empty cache; production wiring must be tested.
- Use the same eligibility/result mapper for list and detail. Do not persist or retain a server-side cache of these results. Use `Cache-Control: no-store` for enriched run-video responses rather than introduce expiry-aware HTTP cache machinery. This prevents this new projection from establishing a reusable response cache; it does not promise deletion of data a client already received or constant metadata across separate reads.
- No YouTube call, refresh option, alternate channel-table lookup, metadata mutation, new schema, causal inference or historical backfill is part of this seam. Known source-channel ID remains the existing video association; a separate subscription identity is not inferred. Do not log metadata values or raw database errors. Existing safe diagnostic classification may describe the lookup failure without its payload.

**Affected realization surfaces:** `cmd/server/main.go` (inject existing manager); `internal/server/server.go` (narrow interface/field/option and explicit unconfigured behavior); `internal/server/run_handlers.go` (one shared optional context projection after mandatory evidence); `internal/metadata/{models,manager,store}.go` (minimal display result, batch eligibility and bounded local query). Existing metadata/server tests are verification seams; a production-wiring composition test must pass the actual manager/Store, not only a shaped reader double. New migrations, pipeline evaluation and state transaction changes are unnecessary. The linked ARS supplies the exact API/browser contract and attributes the targeted reader/API/SPA proof; the full historical-capture contract remains blocked.

Delaying a lookup past expiry must withhold its result at projection. Route/action evidence must remain byte-for-byte unaffected by metadata rename/expiry. ### Capture boundary — independent rule identity, compared input remains gated

The exact config-only reference and its confirmation requirements are selected in ADR-001. Persisting which configured occurrence caused a **new** skip is independent of retaining the provider value compared. The paragraphs below retain the full-evidence direction, but do not gate this source-content-free reference on raw-input permission or claim that a pointer reproduces the original comparison. No new predicate-value copy, actual input, substring or hash belongs to the independent reference.

The exclusion predicate must return the actual first causal match with comparison meaning, not just a skip enum. Both all-route filtering and ordinary routing consume that same result shape. A disabled/final-skipped route must not acquire an exclusion match by later recomputation. Fully excluded videos need one attributable causal match for each enabled route that actually excluded them; partial exclusions remain attached to their route. There is no requirement to enumerate every matching exclusion.

Reuse the run's immutable configuration. The minimal predicate identity is its configuration version, route identity and exclusion array position in that exact snapshot. Preserve the snapshot array order used during evaluation. Do not use an ordinal from a newly sorted list or a current exclusion row ID. Resolve and validate the reference against the producer's actual snapshot; a missing/invalid reference stays incomplete, not silently redirected.

At the conceptual state seam, extend a route evaluation with optional causal-exclusion evidence, separate from condition audits: predicate reference; comparison semantics/version; recorded match; and an attributable compared-input value or explicit availability. The comparison must describe real semantics, not merely a friendly label: current exact-title exclusion trims and folds case, word exclusion uses case-insensitive substring matching, and duration excludes strictly outside the configured bound. New evidence must preserve these meanings without changing predicates. Snapshot references avoid duplicating configured text; they do not authorize release of unsafe predicate values.

The evidence and decision must commit together through the existing route-evaluation transaction. New complete captures cannot publish a generic decision and attach the cause later. Existing tuple reuse returns the original evidence unchanged, including legacy absence. A resumed legacy generic skip must not acquire an exclusion inferred from today's input, even when it seems obvious. Missing evidence is not an invitation to overwrite history. The state transaction owner decides SQLite contention mechanics under the existing durability guarantee.

Use one prepared input context for each actual comparison and capture from that value at that point. The gate and router must not label a second metadata read as the input of the first comparison. If a mode performs separate comparisons, their inputs remain attributable separately; this design does not introduce a run-wide metadata snapshot guarantee. Conditions keep their recorded order/composition and actual leaf results. An evaluated empty string may be the engine's degraded input, but it is not proof of an observed empty provider field; capture both meanings rather than inventing a provider value. Existing missing-data evaluation semantics must not be silently changed here.

Use the additive nullable `exclusion_index`/`exclusion_semantics_version` extension to `route_decision` and the existing atomic write/reuse seam, not a second ledger. ADR-001 fixes identity; ARS-002 specifies columns, validation, conflict readback, safe `causal_exclusion` list/detail objects and `route_name_source`. No compared-input storage is included. The all-route gate must retain fresh route/match pairs separately from stored recovery results; the SPA list mapper must stop dropping route decisions. Legacy authority comparison must preserve existing checks without comparing null old pointers to new expected pointers or enriching old rows. If approved raw comparison values later require distinct expiry, use a logical restricted-input child relation rather than permanent JSON diagnostics; its permission remains blocked. **No new raw-value columns, retention defaults or full per-video metadata archive are authorized.**

## Retention, safety and unresolved authority

The [official Developer Policies](https://developers.google.com/youtube/terms/developer-policies?hl=en), III.E.4(c–f), reviewed by the researcher on 2026-11-06, distinguish storage/refresh obligations from historical presentation. The reported text limits other Authorized Data to “no longer than 30 calendar days” before deletion or refresh; a similar limit covers limited Non-Authorized Data. Historical time-labeling is not an express storage exemption. The [derived-metrics policy](https://developers.google.com/youtube/terms/derived-metrics-policy) says other data, including “video titles, creator names, descriptions, and comment text”, must still follow the 30-day refresh/deletion policy. Approval for qualifying metrics is not established permission for arbitrary rule Booleans or source text. This is source-backed research, not legal advice or a granted exception.

The accepted system architecture's **INV-9**, not INV-5, carries the metadata-lifecycle guarantee. INV-5 is configuration attribution. BR-015/OC-005's reference to INV-5 as expiry is a citation error; their stated substantive conflict is real. The older [proposed compliance analysis](../../yuhaul-youtube-compliance.md) cannot establish that every audit field is app-owned, that all accepted behavior works on fingerprints, or that current refresh permits keeping superseded text.

The required boundary, whichever permitted retention basis is selected:

- Classify by source and content, not table name. Actual API title/name/description/duration remains provider-origin when copied into an audit. An imported API-origin title does not become independent user content merely through import.
- Independently authored configuration is different from provider-returned input. Release only the relevant typed predicate through a domain-evidence policy; never dump snapshots, OAuth settings, provider bodies, request data or raw errors. Copied provider metadata inside a predicate needs its own origin treatment. This artifact does not declare arbitrary configured strings safe or permanently retainable.
- Safe domain evidence is not a diagnostic. Do not run every predicate through a generic diagnostic-summary replacement that destroys the cause; conversely a printable string is not proof that it contains no secret. When release is unsafe, withhold the value explicitly and retain only permitted structural evidence.
- Any approved expiring input copy must inherit its original source observation/deadline. Evaluating a 29-day-old cached title does not create a new 30-day retention period. Refreshing today's metadata does not extend the old snapshot's deadline or replace its captured input.
- Expiry must cover all restricted copies, including condition actual values, exclusion inputs, caches and released projections. Read-time gating prevents disclosure if cleanup lags but does not satisfy a deletion obligation. Storage lifecycle enforcement must be independently proved.
