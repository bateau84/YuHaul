# Architecture

- [YouTube authorization](youtube-authorization/index.md) - Decided shared automatic renewal with encrypted commit-before-use, per-request authority/expiry fencing, coherent account status and a minimal durable uncertain-mutation veto. BR-034/OC-006 cover scheduled/manual production and restart/concurrency; no blind playlist replay, historical-run restart, simulation calls, multi-writer support or live incident repair. Exact persistence/API/diagnostic/legacy admission and required composition proofs are specified; implementation/verification remain outstanding.
- [Run initiation](run-initiation/index.md) - Accepted 2026-11-10 realization of BR-017 AC7–12 and BR-027 AC8–13. Run Now resumes the oldest Run Now run stopped by its time limit, identified by explicit `interrupt_cause`/`initiated_by` fields, admitted atomically under the production lock; a press during an active run gets `409`. Backtest/Replay filter by a UTC published-day range stored immutably on the run, with the date taken only from an eligible local metadata row and no provider call. Migration 024, the API contracts and a 33-test list are in ARS-001. Implemented 2026-11-10, review pending; deviations are in ARS-001 §10. Discarding the run Run Now cannot resume (BR-017 AC13–21) is specified in ADR-003/ARS-002 (one transaction under the production lock). Stopping an active run (BR-035) is specified in ADR-004/ARS-003: a durable marker plus a cause-tagged cancel, the new status `stopped` (migration 025), and one deferred-queue handoff shared with Discard. Startup settles stops and no longer exits on an unusable time-limit Run Now run (ADR-005 amended). Discard and Stop are implemented in the backend 2026-11-10, review pending (ARS-003 §9); the frontend is not.
- [Decision evidence and metadata lifecycles](decision-evidence/index.md) - Accepted current/local metadata ARS documents implemented list/detail recognition. ADR-001/ARS-002 select future config-only causal exclusion identity in the immutable run snapshot, with no compared-provider-input storage; implementation remains outstanding. Under the user's 2026-11-10 amendment of BR-015 AC7, past inputs are current/local or “unavailable” and configured values are always shown, so historical reproduction is no longer required. BR-009 durable titles for duplicate detection remain open. No indefinite input storage or historical backfill is authorized. Targeted local-reader proof is attributed, not whole-product acceptance.
- [Run 14 recovery assessment](run14-recovery/index.md) - **Declined by the user 2026-11-10** (no recovery, no backfill); kept as history. Originally a proposed evidence-gated incident recommendation. Distinguishes existing no-discovery queue retry from missing arbitrary-pending admission; requires current status/activity/attempt/budget evidence before intervention. Corrects the dry-run API-cost assumption: inspected evaluation is local cached work, not metadata fetching. No live operation or code change.
- [Discovery, processing, and budget coordination](discovery-processing-coordinator/index.md) - Proposed source-grounded assessment of independently controlled discovery/processing jobs and a coordinator within the existing process. Reuses SQLite backlog/history, scheduler and ledger; identifies durable admission, page/watermark preservation and shared request budget gaps. User direction of 2026-11-10 (automatic separate schedules; quota exhaustion acceptable) is recorded but not accepted as requirements; bootstrap scope, limits, fairness and pause semantics remain owner decisions. No implementation or live-run intervention.
- [YuHaul System Architecture](yuhaul-system-architecture.md) - Compliance-aware system architecture for YuHaul — two-store data model, processing pipeline, quota management, duplicate detection, deployment model, direct SQLite historical-corpus migration, Traefik BasicAuth ingress boundary, and stable UUID route identity. Updated 2026-10-25; 32 BRs and 4 OCs are mapped. Route-scoped exclusion precedes duplicate detection and route evaluation (BR-008 AC7): all-route-excluded videos are classified before detector lookup and produce no new DuplicateMatch/provenance row, while partial exclusions continue. Production/recovery, replay/backtest, and dry-run now implement this order with assembled SQLite-backed regressions. The subsequent user decision fixes duplicate continuation in every mode; ADR-017/ARS-005 retire effective skip, preserve legacy input/history, and identify pending replay/backtest short-circuit, settings readback, and successful-result counting corrections. No new implementation verification is claimed. Imported history remains eligible across same-ID native fingerprint upserts, while exact matching compares canonical title fingerprints across distinct video IDs and both detector passes exclude the evaluated video's own ID (ADR-013/014, ARS-002). Eligibility creates no route or discovery credit. Existing route-identity and ingress status records remain in their respective artifacts; non-local ingress requires cluster-side Traefik/TLS/credential provisioning and verification.
  Discovery attribution follows user-approved BR-010 AC7–AC8: retain each selected matched pair and available channels; native chronology determines discovery/relevance or leaves both unknown. A–B/B–C matches do not establish A–C or propagate credit, and no global fuzzy-group origin or all-candidate enumeration is promised. The new chain confirmation remains unverified by this documentation reconciliation.
- [Run outcome diagnostics](run-outcome-diagnostics/index.md) - Accepted bounded realization is implemented: nullable selected count, decision-bearing count, truthful run status, action outcomes/reasons, attempt-only route statistics, vetted diagnostics, pagination, and real-client SPA build configuration. ARD-001 records passing local composition tests and representative production/queue, no-token, nonzero dry-run and actual Backtest browser journeys, with attributed evidence and limits. Date selection (BR-027 AC8–13) is implemented per run-initiation ADR-002, review pending; comparison remains deferred; counts do not prove membership and provider/local-record uncertainty remains. No full container/deployment, live-Google or accessibility certification.
- [YouTube API Compliance Analysis](yuhaul-youtube-compliance.md) - Analysis of YouTube Developer Policies data-retention requirements and their impact on YuHaul's storage model.
- [ADR-001 — YouTube Provider Seam via Base URL Override](adr-001-youtube-provider-seam.md) - Accepted and implemented: threads `youtube.WithBaseURL` through the shipped binary behind `YUHAUL_YOUTUBE_BASE_URL`. Run-diagnostics browser evidence now exercises the binary through this seam with real auth-store/service and quota wiring; synthetic auth state does not prove OAuth acquisition/refresh or live-Google compatibility. Older PA-001's complete assertions are not retroactively certified.
- [ADR-002 — Failed-Phase Runs Terminate as `failed`, Not `completed`](adr-002-run-status-failed-terminal-state.md) - Accepted and realized across production and simulation failure/panic paths; unrecoverable phase failure is terminal `failed`, interruption stays resumable, and failed runs are excluded from auto-resume. Finalization failure can fall back to `interrupted`; exhaustive crash proof is not claimed.
- [ADR-003 — Route Deletion Is a Soft Delete That Preserves Historical Decision Evidence](adr-003-route-soft-delete-preserve-history.md) - Soft-deletes routes via `deleted_at` so `route_decision`/`condition_audit`/`executed_action` and historical statistics survive deletion (BR-003 AC4, AC15/25/28).
- [ADR-004 — Canonical Condition Operator Vocabulary Is the Accepted Design Spec](adr-004-condition-operator-vocabulary.md) - Realizes the accepted spec's operators (`starts_with`/`ends_with`/`matches_regex`/`greater_than`/`less_than`/`between`) as the engine's single canonical set, retiring the drifted `gt/gte/lt/lte/not_*`/`in_list` vocabulary.
- [ADR-005 — Complete `GET /api/playlists` Listing for the Action Playlist Picker](adr-005-playlist-listing-endpoint.md) - Returns all playlist pages through one API response, records one quota unit per successful page, and has fake-provider pagination/failure test coverage.
- [ADR-006 — Route List Match Count Is a Production-Evidence Projection](adr-006-route-list-match-count.md) - Makes `GET /api/routes` the sole supported match-count surface and counts distinct matched videos from production evidence over the Route List's lifetime scope; the per-route stats path is not registered.
- [ADR-007 — Canonical Route Action Type at the API Boundary](adr-007-canonical-route-action-type-api-boundary.md) - Uses accepted-design `add_to_playlist` in API payloads while preserving internal `playlist_insert` storage and historical records; route, run-detail, history, dry-run, and backtest tests pass.
- [ADR-008 — Route Drag Reordering Uses the Current dnd-kit React API](adr-008-route-drag-reordering.md) - Implements the current `@dnd-kit/react` sortable API while preserving Move Up/Down controls; automated tests/build pass, with real touch/pen and scrolling verification still outstanding.
- [ADR-009 — Web Corpus Import Uses an In-Process Async Job](adr-009-web-corpus-import-job-lifecycle.md) - Chooses temporary in-process job status for direct SQLite corpus import progress/cancellation without durable job storage; Settings can recover status after navigation in the same process, while process restart loses job state but retains committed rows for append retry.
- [ADR-010 — Protect YuHaul Ingress with Traefik BasicAuth](adr-010-traefik-basic-auth-ingress-boundary.md) - Applies Traefik BasicAuth on HTTPS, externally cert-manager-managed `yuhaul-tls`, and redirect-only HTTP with an HTTP-01 solver exception. The 2026-10-25 correction adds explicit app `router.tls: "true"` and documents operator-owned Ingress-provider `allowEmptyServices: true`; rejects sole reliance on shared entrypoint TLS, app-backed HTTP, or another sink workload. Narrow local corrected-provider transport/redirect checks pass; remaining auth/failure-injection checks, independent re-review, and cluster readiness remain pending. Port-forward remains an intentional bypass.
- [ADR-011 — Stable UUID Route Identity Independent of Display Name](adr-011-stable-uuid-route-identifiers.md) - Adds immutable UUID route IDs while keeping internal integer keys and historical FKs; accepted BR-003 AC10/12/13 and the accepted design amendment settle duplicate display names, stable identity, and short-suffix presentation.
- [ADR-012 — Proposal-Only Routes Use Inactive Identity Anchors](adr-012-proposal-route-identity-anchors.md) - Maps valid proposal-only UUIDs to durable integer keys and inactive soft-deleted route anchors so dry-run/backtest decisions satisfy the existing route FK without changing active routes or snapshot evidence.
- [ADR-013 — Duplicate-Reference Eligibility Is Monotonic Across Fingerprint Upserts](adr-013-monotonic-duplicate-reference-eligibility.md) - Chooses `existing OR incoming` eligibility on same-video-ID fingerprint upserts so native discovery cannot demote an imported reference; exact/fuzzy detection excludes that same ID but retains it as a candidate for other videos.
- [ADR-014 — Discovery Credit Requires Native Earliest-Discovery Evidence](adr-014-discovery-credit-requires-native-earliest-evidence.md) - Reconciles user-approved BR-010 AC7–AC8: retain each observed selected distinct pair and available channels; native chronology assigns earlier discovery/later relevance regardless of detector direction, otherwise both roles remain unknown. Imported associations and self-matches earn no credit. No credit propagates through A–B/B–C chains, and no all-candidate enumeration or global fuzzy-group origin is promised. Reuses `video.channel_id` / `video.discovered_at`, with no schema migration. Attribution scope is resolved; new chain confirmation remains unverified by this documentation-only update.
- [ADR-015 — Persist One Durable Corpus Import Completion Timestamp](adr-015-durable-corpus-import-completion-timestamp.md) - Adds one durable YuHaul operational timestamp for the latest normally completed corpus import, without durable job state, import history, or source content; existing source/video dates are not treated as destination-import completion time.
- [ARS-001 — Route, Playlist, and Run-Outcome API Contracts](ars-001-route-and-playlist-api-contracts.md) - Specifies UUID route references across CRUD/reorder, run decisions, statistics, provenance, history, dry-run, and backtest; channel matched routes are UUID/name/count objects keyed by UUID. Also covers playlist pagination, action naming, distinct-video counts, outcome-filtered pagination, list success/failure envelopes, and historical run-scoped evaluation-order projection that excludes internal soft-delete sentinels. Relevant UUID API surfaces have shipped; Run Detail now exposes the existing API's later pages. See the specification and run-diagnostics design for bounded evidence, not exhaustive browser pagination proof.
- [ARS-002 — Web Corpus Import API Contract](ars-002-web-corpus-import-api.md) - Specifies direct SQLite preview/import, append progress/cancellation, imported duplicate-reference eligibility, process-local job status, actual destination corpus counts, and the configurable 500 MiB default upload cap. Adds migration 013's one-row durable last-successful-import timestamp and `GET /api/corpus/import/metadata`; this metadata extension is accepted target behavior but is not implemented. Existing web import endpoints are implemented; non-local exposure still requires external Traefik BasicAuth/TLS provision and verification.
- [ARS-003 — Traefik BasicAuth and TLS Kubernetes Contract](ars-003-traefik-basic-auth-kubernetes-contract.md) - Defines the exact app TLS annotation, Ingress-provider empty-service prerequisite, redirect-only HTTP sink, BasicAuth, cert-manager `default/yuhaul-tls`, and HTTP-01 priority/DNS-01 alternative. Records independently reproduced v3.7.16 HTTPS 404/plaintext websecure 401 and HTTP route omission; exact per-Ingress corrected proof, port-443 plaintext rejection, failure injection, README reconciliation, and cluster issuance/renewal remain required.
- [ARS-004 — Route UUID Schema, API, and Migration Contract](ars-004-route-uuid-schema-api-migration.md) - Defines append-only UUIDv4 mapping (including historical snapshot-only route IDs), preservation of integer FKs and immutable snapshots, UUID conversion across route APIs/history, and a single-replica Recreate rollout for the migration release. ADR-012 resolves proposal-only route FK realization; migration 012 and the validated startup backfill are implemented, while the public UUID API conversion remains target behavior.
