# Run initiation

Two accepted behaviors from 2026-11-10 decide how runs start. **Run Now** first resumes the oldest Run Now run stopped by its time limit ([BR-017 AC7–12](../../requirements/yuhaul/br-017-manual-run-initiation.md)). **Backtest and Replay** can filter retained videos by YouTube published date, as UTC days with both ends included ([BR-027 AC8–13](../../requirements/yuhaul/br-027-historical-backtesting.md)). Example: run 30 stops at its 30-minute limit. The next Run Now returns run 30 marked `resumed` and continues from its checkpoint under its original rules. A Backtest over `2026-10-01`..`2026-10-31` evaluates only videos whose locally eligible published date falls on those days.

- [ADR-001 — Run Now Resumes the Oldest Time-Limit-Interrupted Manual Run](decisions/adr-001-run-now-resumes-time-limit-interrupted-manual-run.md) — explicit `interrupt_cause` and `initiated_by` run fields, not parsed diagnostic text. The admission runs under the production lock, and a press during an active run is refused with `409` instead of waiting. Unusable candidates fail closed. Startup recovery is unchanged.
- [ADR-002 — Backtest and Replay Select by Locally Eligible YouTube Published Date](decisions/adr-002-backtest-replay-published-date-range.md) — immutable range columns on the run row, validated before anything is created. Only an eligible (unexpired) local metadata row supplies the date, and filtering happens in Go with no provider call. Consequence: ranges over periods with expired metadata select little.
- [ARS-001 — Run Initiation Schema and API](specifications/ars-001-run-initiation-schema-and-api.md) — migration 024 (four columns and trigger guards), the `AdmitRunNow`/`PublishedRange` interfaces, the implementation record, the `POST /api/runs`, `/api/backtest` and `/api/runs/replay` contracts, the `published_range` projection, and the 33-test conformance list.
