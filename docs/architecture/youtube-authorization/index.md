# YouTube authorization

Production requests renew expired access through one shared owner and use replacements only after encrypted durable save. Request admission respects Disconnect and account replacement. A durable exact-target send guard prevents blind replay of a playlist mutation whose application is unknown; renewal is not replay permission.

- [ARD-001 — Shared YouTube Renewal and Mutation Send Safety](design/ard-001-shared-renewal-and-mutation-send-safety.md) — decided technical structure and trade-offs; bounded critique approved/SOUND, implementation and runtime verification outstanding.
- [ARS-001 — Authorization State, Dispatch and Send Guard](specifications/ars-001-authorization-state-dispatch-and-send-guard.md) — exact persistence, interface, status, diagnostic, compatibility and conformance contract, including executor-owned mutation finalization before rejection observation, separate primary/auxiliary failures, atomic quota/authorization deferral and removal-safe retained-work resolution.
- [ADR-001 — Guarded Mutation Dispatch Receipts](decisions/adr-001-guarded-mutation-dispatch-receipts.md) — non-secret binding identity, same-fence admission, exact-target claim/result ownership and application facts independent of accounting failures; bounded critique approved/SOUND, implementation and runtime proof outstanding.
- [ADR-002 — Exact Retry Group Receipts](decisions/adr-002-exact-retry-group-receipts.md) — exact retry identity and removal-aware disposition. Pipeline alone owns ordinary generic failure handoff; one transaction validates the receipt, establishes the receiving-run sink, records failure and resolves surviving sources. Failed guarded handoff instead preserves original claim/guard and reports its storage failure. Bounded ordinary-failure docs critique approved/SOUND; implementation/runtime conformance remains outstanding.
- [ADR-003 — Read Adapter Owns Actual-Call Accounting](decisions/adr-003-read-adapter-owns-actual-call-accounting.md) — actual admission/outcome/time belongs to one client recorder, never post-save manager estimates; rejected/network attempts count once and pre-admission refusals count zero. Coordinated wiring, outcome-aware ledger persistence and runtime proof remain outstanding.

- [ADR-004 — Atomic Quota Admission and Single-Attempt Transport](decisions/adr-004-atomic-quota-admission-and-single-attempt-transport.md) — shared local capacity holds at final fenced dispatch; HTTP/1-only/no-reuse transport suppresses hidden replay. Bounded critique approved/SOUND; implementation/runtime proof outstanding. No user policy decision needed.

- [ADR-005 — Startup Recovery for Guarded Production Runs](decisions/adr-005-startup-recovery-for-guarded-production-runs.md) — exclusive startup classifies only new guarded production orphans, then resumes saved checkpoints through the production gate. No launch flag/lease, historical version promotion, old-guard clearing or automatic version-0 recovery. Implemented; verified by the round 4 final review on the assembled binary (child-process kill/SIGTERM tests), no material defect.

- [ADR-006 — Per-Video Action Failure Isolation and Stranded-Work Retention](decisions/adr-006-per-video-action-failure-isolation-and-stranded-work-retention.md): a handled per-video failure, including a guard block, commits `failed` plus an active error entry in one transaction, and the run continues with independent videos. A run-stopping failure retains all unfinished work (requeues still-owned retry groups, adds runtime error entries for other videos) before `failed`, or otherwise interrupts. No guard is released or replayed. Implemented with its ten tests; the cancellation case was completed by ADR-007. Verified by the round 4 final review, no material defect; tests 2, 3, 5, 6, 8, 9 and 10 are integration-only.
- [ADR-007 — Asynchronous Startup Resume and Shutdown Interruption](decisions/adr-007-asynchronous-startup-resume-and-shutdown-interruption.md): synchronous classification, then the HTTP listener, then background resume behind a pipeline producer gate (`503` for manual starts and queue retries); the scheduler starts after the drain. SIGTERM cancels the process context, and cancelled runs become `interrupted`. The manifest gets `terminationGracePeriodSeconds: 60`; no startup probe is needed. Queue retries share the same context, drain and shutdown refusal. Implemented with its nine tests plus two for queue retries. Verified by the round 4 final review, no material defect. Unproven: SIGTERM during classification, two-run no-overtake, drain overrun, the real 30-minute deadline, Kubernetes and the `wedge_save` timing window. Advisory: `/api/account` reports `persistence_failed` after a cancelled save until the next token use, then heals.

The shared parent [architecture log](../log.md) governs this topic. No live-account operation, failed-run restart, simulation provider call, date policy or multi-writer capability is authorized.
