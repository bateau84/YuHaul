# Live status

Proposed 2026-11-19 (revised after critique the same day) realization of [BR-042](../../requirements/yuhaul/br-042-skip-live-and-upcoming-videos-until-ended.md) (skip live and upcoming videos until they have ended). Every production pass, including every resume, gets a fresh live status from the run's own by-ID `videos.list` read before exclusions, duplicates, routing, capacity checks and adds. The run records it on its own `run_video_outcome` row. Claimed paths require ARS-005 §6.1–6.2, which is not built. Anything not clearly "neither live nor upcoming" is deferred on one reused queue item and checked again on the next run. Not implemented. Critique pending.

- [ARD-001 — Fresh Live-Status Gate Before Exclusions, Routing and Sends](design/ard-001-fresh-live-status-gate.md) — Adds a `Live` requirement to `FetchForEvaluation` and keeps a non-expiring run-scoped clearance on `run_video_outcome`. Fail-closed classification from `liveBroadcastContent` and `liveStreamingDetails`. A `live_hold` overlay keeps the original queue reasons. Native retention for new discoveries. Fence and backstop refusals end deferred, never failed. Composition with BR-039, capacity, BR-037 and simulations. Version-0 continuation is recorded as unreachable.
