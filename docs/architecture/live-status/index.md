# Live status

Proposed 2026-11-19 (revised after critique the same day) realization of [BR-042](../../requirements/yuhaul/br-042-skip-live-and-upcoming-videos-until-ended.md) (skip live and upcoming videos until they have ended). Every production pass, including every resume, gets a fresh live status from the run's own by-ID `videos.list` read before exclusions, duplicates, routing, capacity checks and adds. The run records it on its own `run_video_outcome` row. Anything not clearly "neither live nor upcoming" is deferred on one reused queue item and checked again on later runs. Amended 2026-11-22 for AC7: those checks stop after the user-set live check limit (default 30 days, 1–365), the item stays deferred and visible, and Retry now checks again with a fresh window. Claimed paths require ARS-005 §6.1–6.2, which is not built. Not implemented. The AC7 amendment awaits critique.

- [ARD-001 — Fresh Live-Status Gate Before Exclusions, Routing and Sends](design/ard-001-fresh-live-status-gate.md) — Adds a `Live` requirement to `FetchForEvaluation` and keeps a non-expiring run-scoped clearance on `run_video_outcome`. Fail-closed classification from `liveBroadcastContent` and `liveStreamingDetails`. A `live_hold` overlay keeps the original queue reasons. Native retention for new discoveries. Fence and backstop refusals end deferred, never failed. The AC7 check window is a column next to the hold, with exclusion on automatic claims. Composition with BR-039, capacity, BR-035 AC14, BR-037 and simulations. Version-0 continuation is recorded as unreachable.
